# Ten-minute interview walkthrough

Start from a fresh explicitly reset demo, or clearly disclose any earlier runs. Enable observability. Choose Admin. Keep LOAN-1001 unpaid for the first example; the simulator business date is 2026-10-31 independently of the machine's clock.

1. **0:00–1:30 — Loan policy.** Open LOAN-1001. Explain frozen reducing-balance schedule, satang strings, month-end dates and actual vs scheduled principal. In Simulator set 1 RPS, 1 second, fixed LOAN-1001, 900000 satang. Start. Inspect first allocation and journals: 1000 THB interest, 8000 principal, 92000 actual balance.
2. **1:30–2:30 — Deduplication.** Select the run in Reconciliation. Re-deliver its original bank transaction using the Admin API/recorded transaction control; alternatively use Duplicate Storm on another unpaid loan. Payment receipt attempts increase while the payment journal count remains one. Explain event vs transaction uniqueness and immutable-field review.
3. **2:30–4:30 — Spike and scaling.** On Kubernetes choose Month-End Spike. Show target vs achieved RPS, scheduling lag, real queue depth and ready workers on one time axis. Receiver scales by CPU; workers by KEDA queue length. Tell the interviewer these are observed single-machine results, not production capacity guarantees. Additional monthly payments against already paid due schedules intentionally become credit review.
4. **4:30–5:30 — Worker recovery.** While there is a backlog, delete a loan-worker pod. Show the replacement and recovered deliveries, then payment/journal uniqueness. The automated integration test also closes a real broker connection after financial commit and before ACK, observes redelivery, and verifies one journal.
5. **5:30–6:30 — Broker outage.** Stop Compose RabbitMQ, or temporarily scale the Kubernetes RabbitMQ deployment to zero. Send a small run. Show durable receipt and unpublished outbox. Restore the broker; publication and allocation resume. Keep the recovery commands ready and always restore the dependency.
6. **6:30–7:30 — Unmatched recovery.** Start a 1 RPS/1 second run with unknown references at 100%. In Failures & Recovery resolve the original reference to an existing loan, then replay. Show original bank ID, mapped reference and before/after audit. Replay again to show prior financial outcome.
7. **7:30–8:30 — Reconciliation.** Start Missing Webhook (use a small duration). Wait past grace, compare settlement, recover a MissingReceipt row. Compare again after application: matched count/amount increase once even after another redelivery.
8. **8:30–10:00 — Tradeoffs.** Durable receipt before eventual allocation; at-least-once transport plus idempotent ledger; one transactional financial boundary; CPU vs queue scaling; bounded connections/prefetch; one computer and non-HA dependencies. Switch to Observer and demonstrate that operational mutations are denied by the backend.

Fallback when Kubernetes is unavailable: perform the financial, duplicate, outage, unmatched and reconciliation demonstrations in Compose. The UI labels autoscaling unavailable; use recorded Kubernetes evidence only if it was actually observed. Do not animate/claim replicas or throughput without data.
